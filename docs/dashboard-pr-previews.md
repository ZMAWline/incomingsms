# Dashboard PR previews

IncomingSMS dashboard review is Vercel-like: a dashboard change is not `ready to review` until it has a working, login-testable preview URL in the review message.

If code is complete but no preview URL is live, use `needs-preview` / blocked status instead of `ready to review`.

## What the workflow does

`.github/workflows/dashboard-pr-preview.yml` deploys a per-PR Cloudflare Worker for dashboard-relevant pull requests:

- PR open/synchronize/reopen: run tests, generate a preview Wrangler config, verify required preview/test secrets are present, dry-run deploy, deploy `dashboard-pr-<PR_NUMBER>`, upload preview/test secrets, smoke-test the auth challenge, and comment the preview URL on the PR.
- PR close: delete `dashboard-pr-<PR_NUMBER>` so stale Workers do not accumulate.
- Manual `workflow_dispatch`: deploy or clean up a selected PR number.

The preview config is generated by `scripts/deploy-dashboard-preview.mjs` from `src/dashboard/wrangler.toml` `[env.test]`. This keeps the preview on dashboard test bindings (`*-test`) instead of production service bindings.

Default URL shape:

```text
https://dashboard-pr-<PR_NUMBER>.zalmen-531.workers.dev
```

If the account's `workers.dev` subdomain changes, set repository variable `WORKERS_DEV_SUBDOMAIN`.

## Required GitHub permissions and secrets

Pushing or updating `.github/workflows/*.yml` requires a GitHub token with `workflow` scope. If `git push` is rejected for workflow scope, Zalmen/admin should run:

```bash
gh auth refresh -h github.com -s workflow
```

or reissue the GitHub token with workflow permission.

Required repository secrets:

- `CLOUDFLARE_API_TOKEN` - token that can deploy/delete Workers for account `5313f8b98e20a8915418b2683ad7278c`.
- `CLOUDFLARE_ACCOUNT_ID` - Cloudflare account id.
- `DASHBOARD_PREVIEW_AUTH` or `DASHBOARD_TEST_AUTH` - Basic Auth value for login testing, formatted `username:password`.
- `DASHBOARD_PREVIEW_SUPABASE_URL` or `DASHBOARD_TEST_SUPABASE_URL` - test Supabase URL only.
- `DASHBOARD_PREVIEW_SUPABASE_SERVICE_ROLE_KEY` or `DASHBOARD_TEST_SUPABASE_SERVICE_ROLE_KEY` - test Supabase service-role key only.

Optional preview/test secrets, when the dashboard path being reviewed needs the corresponding worker operation:

- `DASHBOARD_PREVIEW_ADMIN_RUN_SECRET` or `DASHBOARD_TEST_ADMIN_RUN_SECRET`
- `DASHBOARD_PREVIEW_BULK_RUN_SECRET` or `DASHBOARD_TEST_BULK_RUN_SECRET`
- `DASHBOARD_PREVIEW_CANCEL_SECRET` or `DASHBOARD_TEST_CANCEL_SECRET`
- `DASHBOARD_PREVIEW_FINALIZER_RUN_SECRET` or `DASHBOARD_TEST_FINALIZER_RUN_SECRET`
- `DASHBOARD_PREVIEW_STATUS_SECRET` or `DASHBOARD_TEST_STATUS_SECRET`
- `DASHBOARD_PREVIEW_SYNC_SECRET` or `DASHBOARD_TEST_SYNC_SECRET`
- `DASHBOARD_PREVIEW_RELAY_URL` or `DASHBOARD_TEST_RELAY_URL`
- `DASHBOARD_PREVIEW_RELAY_KEY` or `DASHBOARD_TEST_RELAY_KEY`
- `DASHBOARD_PREVIEW_HX_TOKEN_URL` or `DASHBOARD_TEST_HX_TOKEN_URL`
- `DASHBOARD_PREVIEW_HX_CLIENT_ID` or `DASHBOARD_TEST_HX_CLIENT_ID`

- `DASHBOARD_PREVIEW_HX_GRANT_PASSWORD` or `DASHBOARD_TEST_HX_GRANT_PASSWORD`

Never put production Supabase, production carrier, or production customer-impacting credentials into preview secrets.

## Local commands

Generate a preview config without deploying:

```bash
node scripts/deploy-dashboard-preview.mjs generate --pr 42 --sha local
```

Dry-run the deploy:

```bash
set -a
source /home/paperclip/.config/paperclip-ceo-env
set +a
node scripts/deploy-dashboard-preview.mjs deploy --dry-run --pr 42 --sha local
```

Delete a preview Worker:

```bash
set -a
source /home/paperclip/.config/paperclip-ceo-env
set +a
node scripts/deploy-dashboard-preview.mjs delete --pr 42
```

Generated configs are named `src/dashboard/dashboard-pr-<PR>.wrangler.toml` and are ignored by git. The generated file sits next to the dashboard source so Wrangler resolves `main = "index.js"` and `assets.directory = "./public"` exactly like the normal dashboard config.

## Review-message rule for Kanban/Hermes workers

Use this format only after the preview URL is live and login-testable:

```text
Ready to review: <branch or PR>
Preview: https://dashboard-pr-<PR>.zalmen-531.workers.dev
Commit: <sha>
Tests: <targeted tests>
Notes: preview uses dashboard test bindings; destructive/carrier paths are disabled/mocked or backed by test-safe secrets.
```

If any of these are missing, do not say `ready to review`. Say `needs-preview` or block with the exact missing permission/secret/deploy failure.
